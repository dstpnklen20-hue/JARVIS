## Этап 0 — каркас

**Сделано:** Cargo workspace, конфиг (`default.toml` + `user.toml`) со строгой проверкой, логи с
ротацией, `jarvis --check`, скрипт скачивания моделей с проверкой SHA-256, `CLAUDE.md`, `README.md`.

**Окружение:** Windows 11 Pro 24H2, Core Ultra 9 275HX (24 потока), 32 ГБ, RTX 5070 Ti. Rust 1.99 и
VS 2022 Build Tools поставлены через winget.

| Решение | Почему |
|---|---|
| Workspace прямо в `F:\JARVIS`, а не в подпапке `jarvis/` | ваш выбор; ТЗ лежит рядом и попадает в git |
| Крейты создаются по мере надобности, а не все сразу | пустые заглушки только мешают; на этапе 0 — `core`, `platform`, `app` |
| `user.toml` накладывается поверх `default.toml`; ключ, которого нет в `default.toml`, — ошибка | опечатка в имени параметра ловится сразу, а не молча игнорируется |
| Все ошибки конфига выводятся сразу, с файлом, параметром и причиной | не нужно чинить по одной |
| Ошибки не повторяют причину в тексте, цепочку печатает `error_chain` | раньше сообщения дублировались |
| Описание ресурсов в одном файле `scripts/assets.json` | его читают и скрипт скачивания, и `--check` — нет расхождений |
| Метка `.jarvis-verified` с хешем архива в папке ресурса | `--check` за миллисекунды знает, что папка из проверенного архива нужной версии |
| `curl.exe` + `tar.exe` вместо `Invoke-WebRequest`/`Expand-Archive` | первый оборвал загрузку 1.9 ГБ без докачки, второй очень медленный |
| `.ps1` со строками на русском — в UTF-8 с BOM | Windows PowerShell 5.1 иначе читает их как ANSI |
| Время в логах местное | по UTC неудобно сверять события |

## Этап 1 — слух

### Главное решение: замена устаревших компонентов ТЗ

Перед этапом выяснилось, что часть предложенных в ТЗ компонентов давно не обновлялась. Вы
попросили взять лучшие актуальные альтернативы. Варианты проверены прототипом на тестовых фразах.

| В ТЗ | Проблема | Выбрано | Почему |
|---|---|---|---|
| `rustpotter` (wake word) | без обновлений с 2023 | потоковое распознавание русской речи + поиск слова «джарвис» + проверка голоса | английский keyword spotting (sherpa-onnx, gigaspeech) не услышал русское «Джарвис» даже при минимальном пороге; русская модель слышит его и стоит 1.7% одного ядра |
| `vosk` + libvosk 0.3.45 | крейт — 2024, сборка под Windows — 2022 | sherpa-onnx (k2-fsa, официальный Rust-крейт, 2026) + `zipformer-small-ru-vosk` (2025) | это новое поколение моделей той же команды Vosk: потоковая, частичные результаты, 23 МБ |
| полная модель Vosk 0.42 (1.9 ГБ) | — | GigaAM v3 (Сбер, 2025) на этапе 7 | точнее и в 10 раз меньше |
| `webrtc-vad` | без обновлений с 2019 | Silero VAD (TEN VAD — альтернатива в конфиге) | оба в sherpa-onnx, 0.2% CPU |
| обучение wake word на голосе (rustpotter) | — | `jarvis --enroll`: 5 записей → вектор голоса (CAM++) + как модель слышит ваше «Джарвис» | отсекает чужие голоса и ТВ; заодно подстраивает словарь под ваше произношение |

Отвергнуто: **T-one** (Т-Банк) — распознаёт точнее всех, но работает на 8 кГц кусками по 300 мс,
текст готов через 0.7–1 с; **Porcupine** — закрытый, нужен ключ; **openWakeWord** — для своего слова
нужно отдельное обучение на Python (можно добавить позже за тем же трейтом `WakeWordEngine`).

### Остальные решения этапа

| Решение | Почему |
|---|---|
| Архив нативной библиотеки sherpa-onnx качает наш скрипт с проверкой SHA-256 (хеш совпадает с опубликованным на GitHub), сборка берёт его через `SHERPA_ONNX_ARCHIVE_DIR` | сборочный скрипт крейта качает библиотеку без проверки |
| Статический рантайм C (`crt-static`) | библиотека собрана с `/MT`; два рантайма C в одном процессе — разные кучи (было предупреждение LNK4098). Плюс: `jarvis.exe` не требует `vcruntime*.dll` |
| Звук ответа через `cpal` напрямую, без `rodio` | `rodio` 0.22 тянул вторую копию `cpal`, 0.23 вышел в день разработки; свой проигрыватель на 150 строк держит поток вывода открытым — ответ без задержки на открытие устройства |
| Ресемплинг 48 → 16 кГц — FFT-ресемплер `rubato` | качественный антиалиасинг (проверено тестом: 12 кГц подавляется, а не заворачивается) |
| Callback микрофона и вывода: только копирование через lock-free `ringbuf`, без блокировок и аллокаций | требование ТЗ к потоку реального времени |
| Срабатывание по **частичному** результату распознавания | «Джарвис» ловится, пока слово ещё дописывается («джарви»): в среднем на 100–200 мс раньше |
| Сопоставление слова: расстояние Левенштейна ≤ 1, но не больше трети длины; слова короче 4 букв не сравниваются | ловит «жарвис», «джарвиз», «джавис»; не ловит «дарвин», «сервис», «джаз» |
| Поток распознавателя **пересоздаётся**, а не `reset()` | `reset()` в sherpa-onnx не сбрасывает энкодер: хвост прошлой фразы превращал «джарвис» в «орвис» (поймано тестом) |
| Встроенное правило «2 с тишины → сброс» не исполняется вслепую | модель видит речь с задержкой, сброс мог прийтись на начало слова; теперь на пустой тишине сброс только когда звук действительно тихий, после законченной фразы — сразу; поток не длиннее 60 с |
| Порог сходства голоса — между 0.30 и 0.55, запас 0.20 от худшего образца | синтетика даёт 0.96–0.98, и порог упирался в 0.70; живой голос меняется сильнее (0.5–0.8) — при 0.70 были бы частые отказы. Чужие голоса — меньше 0.3 |
| Пока Джарвис говорит, на вход подаётся тишина (`MuteGate`) | он не слышит сам себя (раздел 4.1 ТЗ); время потока при этом идёт |
| На паузе микрофон закрывается полностью | гаснет индикатор микрофона Windows |
| Сбой буфера микрофона (xrun) не считается потерей устройства | в первом живом тесте микрофон переоткрывался каждые 2 с — само переоткрытие вызывало новые сбои |
| Конвейер слуха в отдельном потоке под присмотром: паника → перезапуск (до 5 раз) | падение не роняет приложение (раздел 10 ТЗ) |
| Пробуждение главного потока — `PostThreadMessageW` + таймер 250 мс | сообщения потоку теряются, пока открыто меню трея; таймер подхватывает накопленное |
| `jarvis --stop` через именованное событие Windows | у фонового процесса нет окна — без этого его не остановить мягко; пригодится установщику |
| `--check` замеряет уровень сигнала микрофона | в живом тесте ME6S отдавал цифровую тишину — теперь это видно сразу |
| Логика ядра на потоках и каналах `std`, без `tokio` | на этапе 1 нечего делать асинхронно; `tokio` появится вместе с сетью (LLM, этап 7) |
| Стандартный звуковой пакет — голос Windows «Pavel» через WinRT, тишина по краям обрезается | мужской голос, без внешних сервисов; обрезка убирает ~100 мс задержки перед «Да, сэр» |
| Тестовые записи синтезируются скриптом и лежат в git (2.6 МБ) | тесты конвейера без живого микрофона (раздел 10 ТЗ) |
| Тесты на моделях помечены `#[ignore]` | моделей нет в git; запуск: `cargo test --release -- --include-ignored` |

Звук из динамиков проигрывался в микрофон при запущенном демоне. Демон запустился, открыл

## Этап 2 — команды

**Сделано:** манифесты команд (`commands/*/command.toml`), пакеты `browser` и `media`;
нормализация (регистр, ё, паразиты, числа словами) и нечёткое сопоставление (`jarvis-nlu`);
исполнители `open_url`, `media`, `say` (`jarvis-actions`); распознавание команды после «Джарвис»;
автомат `LISTENING → EXECUTING → FOLLOW_UP`; раннее решение по частичному тексту; `--bench` для
команд; пункт «Команды» в `--check`.

| Решение | Почему |
|---|---|
| Вместо ограниченной грамматики Vosk — подсказки (hotwords) из фраз команд + нечёткое сопоставление | новая модель не поддерживает грамматику; подсказки при силе 1.5 не искажают речь (при 2.5 «громкость» → «громчесть»), а сопоставление прощает ослышки |
| Словарь `bpe.vocab` для подсказок выгружается из `bpe.model` своим разборщиком protobuf | без Python; формат простой |
| Подсказки только из кириллических фраз | латиницы нет в словаре русской модели — sherpa-onnx не закодировал бы подсказку |
| Один распознаватель на слово активации и команды (два потока) | с двумя копиями модели память была 186 МБ, с одной — 124 МБ (цель ≤ 150) |
| Распознавание команд включается только после «Джарвис» и получает звук **с начала слова активации** из буфера | в простое процессор не тратится; «Джарвис, открой ютуб» на одном дыхании тоже работает |
| Сходство фраз — нормированный Левенштейн по исходному и по отсортированному порядку слов | «ютуб открой» = «открой ютуб»; «выключи звук» и «включи музыку» различаются надёжно |
| Почти равные кандидаты разных команд — «переспросить» (пока звучит «Не понял, сэр») | вопрос «X или Y?» голосом — с синтезом речи на этапе 5 |
| Непонятная фраза в FOLLOW_UP игнорируется молча | скорее всего это разговор в комнате, а не команда |
| Мгновенное решение по частичному тексту: точная фраза или однозначное начало («открой ю…» → «открой ютуб», покрыто ≥ 60 % фразы); иначе — после 300 мс стабильного текста; иначе — по концу фразы | модель выдаёт текст блоками по 0.64 с (её экспорт: `decode_chunk_len = 64`), последнее слово запаздывает на 0.3–0.6 с; без этого среднее было ~800 мс |
| Конец фразы — 800 мс тишины, а не 500 | при 500 фраза рвалась на части («поставь» \| «паузу»): 9–10 из 13 верно против 13 из 13 |
| «но» — слово-паразит | модель часто пишет так «ну» |
| `open_url` — только `http(s)://`, проверка и при загрузке, и перед запуском; запуск через `ShellExecuteW` одним параметром, без оболочки | `file:`, `javascript:` и т. п. из манифеста не должны запускаться |
| Мультимедиа — виртуальные клавиши через один `SendInput` (нажатие и отпускание в одном пакете) | клавиша не может «залипнуть»; скан-коды для игр — этап 4 |
| Действие — в отдельном потоке с перехватом паники и тайм-аутом 10 с; поздний результат игнорируется по номеру | сбой или зависание действия не роняет и не вешает ядро (раздел 2.5) |
| Пути в `say` — строго внутри папки пакета (без `..` и абсолютных) | чужой пакет не может читать файлы вне своей папки |
| Ответ после команды по умолчанию `ok`; мультимедиа — `none` | «Готово, сэр» после каждого «громче» раздражает |
| Ключ ответа «Запрос выполнен» — `ok` (был `done`) | так в примере манифеста из ТЗ |
| В проигрывателе держатся последние 4 произвольных клипа | чтобы память клипа не освобождалась в потоке реального времени |
| `jarvis-app` — библиотека + бинарник | разбор команд и симуляция проверяются тестами на настоящих записях |

На этапе 2 команды выполнялись без вопроса-разрешения (так устроен порядок этапов в ТЗ); этап 3
закрыл это в тот же день, до того как вы могли бы запустить Джарвиса.

## Этап 3 — разрешения

**Сделано:** модель разрешений целиком (раздел 2 ТЗ), окно-вопрос с кнопками, ответ голосом,
журнал действий, аварийная остановка (горячая клавиша и «Джарвис, стоп»), «забудь разрешения»
(голосом с подтверждением и из трея), dry-run (был с этапа 2), пункты «Разрешения» и
«Аварийная остановка» в `--check`.

| Решение | Почему |
|---|---|
| Разрешения — только в `config/permissions.toml`; файлы в папках пакетов не читаются; в манифесте поля разрешений нет (`deny_unknown_fields` отвергает попытку) | скачанный пакет не может выдать себе разрешение (раздел 2.2); проверено тестом с подложенным `permissions.toml` в папке пакета |
| Отпечаток — SHA-256 от пакета, `id` и действия в каноническом JSON (`sha2`, RustCrypto) | поменяли URL/путь — спросит снова (раздел 2.2); на этапе 4 для скриптов в отпечаток добавится хеш содержимого файла |
| Запоминаются только «всегда» и «никогда»; «всегда» для `always_ask` считается разовым «да» | раздел 2.1 и 2.3 |
| `allow_always = true` в `permissions.toml` снимает пометку автора; «забудь разрешения» её не трогает | решает пользователь (раздел 2.3); это его настройка, а не разрешение |
| Битый `permissions.toml` — Джарвис не стартует (и `--check` показывает ошибку) | иначе первая же запись разрешения затёрла бы файл; молча «разрешить всё» тем более нельзя |
| Запись файла через временный файл + переименование | оборванная запись не испортит разрешения |
| Окно-вопрос — системный TaskDialog (Common Controls v6), поверх всех окон, кнопка по умолчанию «Нет» | свои кнопки «Да / Всегда / Нет / Никогда», нативный вид; случайный Enter ничего не разрешит |
| Манифест Common Controls v6 вшивается во все exe через флаги компоновщика в `.cargo/config.toml` | без манифеста `TaskDialogIndirect` не загружается; в том числе для тестовых exe |
| Уведомления Windows (toast) с кнопками — не стал | для обычного exe нужны регистрация AppUserModelID и COM-активация; TaskDialog даёт то же без установки |
| Окно в своём потоке; ответ голосом закрывает его программно; ответы из закрытого окна отбрасываются по номеру | голос и кнопка не конфликтуют |
| Вопрос голосом — общий ответ из пакета («Сэр, разрешите выполнить?»), подробности — в окне | прочитать описание команды голосом сможет синтез речи (этап 5) |
| Голосовой ответ — маленький словарь с приоритетами: «никогда» → отказ (включая «не разрешаю») → «всегда» → «да»; короткие слова сравниваются точно, длинные — с одной ошибкой | быстро и точно (раздел 2.1); «дай» не станет «да», «нести» — «нет» |
| Встроенные команды `builtin:stop` и `builtin:forget_permissions` с двоеточием в id | двоеточие запрещено в манифестах — пакет не может подменить встроенную команду |
| «Стоп» распознаётся в любом активном состоянии, даже во время вопроса и действия | аварийная остановка должна работать всегда |
| Аварийная остановка → пауза с освобождением микрофона; продолжить — из трея | раздел 2.5; на этапе 4 добавится отпускание клавиш и завершение скриптов |
| Горячая клавиша по умолчанию Ctrl+Alt+F12 | на ноутбуке часто нет Pause; F12 с Ctrl+Alt почти никем не занята. Занята — Джарвис предупредит и продолжит работать |
| Журнал действий — JSON Lines по дням (`logs/actions.*.jsonl`), отдельно от технического лога | раздел 2.5; JSON удобно разбирать |
| Новые ответы пакета: `ask`, `denied` | вопрос и вежливый отказ |
| Цикл сообщений передаёт событие `Hotkey` | горячая клавиша приходит в главный поток как WM_HOTKEY |

### Проверено

- 183 обычных теста + 11 на моделях: все сценарии раздела 2 (да, всегда, нет, никогда, тишина,
  `always_ask`, смена действия, чужой пакет), голосовые ответы на записях, «стоп», «забудь разрешения».
- Окно-вопрос открывается и закрывается программно (тест).
- Горячая клавиша нажата программно при запущенном демоне → в логе «аварийная остановка», микрофон
  освобождён.
- Память демона 126 МБ.

## Этап 4 — действия

**Сделано:** `launch_app`, `run_script`, `key_press`, `hotkey`, `system_power`, `sequence` + `wait`,
`media volume_set`; слоты (число, выбор); перезагрузка команд голосом и из трея; пакеты `system`,
`apps`, `examples`; аварийная остановка теперь отпускает клавиши и завершает скрипты.

| Решение | Почему |
|---|---|
| Процессы — `std::process::Command` со списком аргументов, без оболочки; `.bat` — тоже напрямую (Rust ≥ 1.77 сам безопасно экранирует аргументы для cmd.exe) | раздел 2.5; ручной `cmd /C` открыл бы дорогу инъекциям |
| В аргументах `.bat/.cmd` из манифеста запрещены `& \| < > ^ % "` | cmd.exe заново разбирает строку |
| Скрипт — в Job Object; тайм-аут и аварийная остановка завершают всё дерево процессов (`TerminateJobObject`) | иначе дочерние процессы скрипта остались бы жить |
| Job Object **без** «убить при закрытии» | программы, которые скрипт запустил и оставил работать, после нормального завершения скрипта не трогаем |
| Скрипты без окна консоли (`CREATE_NO_WINDOW`), `.ps1` с `-ExecutionPolicy Bypass -NoProfile`, рабочая папка — пакет | не мешает пользователю; политика выполнения не блокирует свой же пакет (разрешение всё равно спрашивается) |
| Вывод скрипта: UTF-8, иначе OEM-кодовая страница системы | на русской Windows консоль пишет в cp866 — без этого в журнале были «кракозябры» (поймано тестом) |
| Клавиши — `SendInput` со скан-кодами + явный список «расширенных» клавиш | для стрелок `MapVirtualKey` не даёт признак E0 — игра получила бы «8 на цифровом блоке» вместо «вверх» (поймано тестом) |
| Зажатые клавиши помнит платформа; отпускание — в `Drop` и при аварийной остановке | «гарантированное отпускание» (раздел 6): ни паника, ни отмена не оставят клавишу зажатой |
| Выключение/перезагрузка/выход — `shutdown.exe` из System32 списком аргументов; блокировка — `LockWorkStation`; сон — `SetSuspendState` | штатные способы без повышения привилегий процесса |
| Точная громкость — Core Audio API через `windows` 0.62 (типизированный COM) | та же версия уже в дереве через `cpal`; ручные COM-вызовы на `windows-sys` — лишний `unsafe` |
| Слоты: число (диапазон) и выбор (список или карта «как сказано → что подставить»); подстановка только в `args`, `url`, `level`, путь — запрещён проверкой манифеста | раздел 2.5: речь только выбирает команду и параметр, путь к программе не управляется голосом |
| Сопоставление со слотами: место слота — метка; в речи перебираются числа в диапазоне и похожие слова из списка | обычное нечёткое сравнение работает дальше без изменений |
| Команды со слотами — только по концу фразы (без решения по началу и по стабильному тексту) | «громкость на сорок» через 0.64 с может стать «сорок пять» |
| В отпечаток разрешения входят слоты и SHA-256 содержимого файлов пакета (скриптов, звуков) | подменили скрипт, не трогая манифест, — Джарвис спросит снова |
| Сторож ядра считает срок от действия (тайм-аут скрипта, сумма шагов цепочки + запас), а не 10 с для всех | иначе законный 30-секундный скрипт считался бы зависшим |
| `say` внутри `sequence` — звук отправляется в ядро сообщением и звучит сразу | поток вывода звука живёт в ядре |
| «Обнови команды» перечитывает пакеты, пересобирает разбор и подсказки распознавателю (подсказки — на уровне потока) | без перезапуска (раздел 5); если не загрузилось ни одной команды — остаётся прежний набор |
| Пакет `examples` с PowerShell-скриптом, а не Python | у вас Python не установлен; пример должен работать сразу |

### Проверено

- ~220 обычных тестов и 12 на моделях; новые: все типы действий на подделке системы, процессы по-
  настоящему (код выхода, вывод, тайм-аут, отмена, отсутствующая программа), пример-скрипт со
  слотом end-to-end, скан-коды, слоты в манифестах и в речи («сорок» → 40, «двадцать пять» → 25,
  «хорошее» → good).
- `--bench`: 22 из 22 команд распознаны верно; команды без слотов — в среднем ~400 мс после конца
  фразы, со слотами — ~0.9–1.1 с (по концу фразы, сознательно).

## Этап 5 — голос

**Сделано:** офлайн-синтез речи за трейтом `TextToSpeech`. Вслух звучат: вопрос-разрешение с
описанием команды и значениями слотов, уточнение «вы имели в виду X или Y?» и предупреждение о
запуске от администратора. Выбор голоса и темпа — в конфиге. Добавлены `jarvis --say`, синтез в
`--check` и `--bench`. Готовые ответы по-прежнему берутся из звукового пакета.

### Выбор движка (раздел 4.5 ТЗ: «Piper или Silero — что надёжнее из Rust»)

**Piper (VITS) через sherpa-onnx.** Обоснование:
- Тот же движок и та же статическая библиотека, что у распознавания: не нужен ни второй ONNX
  Runtime, ни зависимость `ort`, ни Python.
- espeak-ng встроен в sherpa-onnx: числа и знаки читаются словами (тест «40%» → «сорок процентов»).
- Голоса под MIT.
- Silero TTS v4/v5 распространяется как PyTorch-пакет. ONNX-экспорт неофициальный, лицензия
  CC BY-NC (некоммерческая). Из Rust пришлось бы самим писать нормализацию текста и подбор ударений.

### Выбор голоса

Все четыре русских голоса Piper medium оценены одним тестом
(`tts_voice_evaluation` в `crates/jarvis-audio/tests/fixtures.rs`):
- синтезированы 5 типичных фраз;
- синтез распознан нашей же моделью;
- посчитана доля верно услышанных слов.

| Голос | Разборчивость | RTF (fp32) | Загрузка |
|---|---|---|---|
| dmitri (м) | 78% | 0.043 | 613 мс |
| ruslan (м) | 73% | 0.041 | — |
| denis (м) | 71% | 0.043 | — |
| irina (ж) | 90% | 0.044 | — |

**По умолчанию dmitri:** у Джарвиса мужской голос, и dmitri — самый разборчивый из мужских.

Остальные три голоса необязательные (`download-models.ps1 -Full`). irina — самая разборчивая, её
стоит выбрать, если важна разборчивость. int8-версии моделей втрое медленнее (RTF ~0.13) при той
же разборчивости, поэтому выбраны fp32.

### Решения

| Решение | Почему |
|---|---|
| Синтез — в отдельном потоке `jarvis-tts`; ядро шлёт запрос с номером и получает готовый клип | загрузка ~0.5 с и синтез ~0.15 с не должны задерживать ядро; если ядро уже попросило новую фразу, старый результат отбрасывается |
| Пока идёт синтез, звучит не фраза `ask` из пакета, а сразу полный вопрос | так быстрее и без двойного «сэр»; если синтез не удался, звучит фраза из пакета |
| Пока фраза звучит, ожидание ответа продлевается на её длительность (событие `Spoke` в автомате) | микрофон в это время заглушён (эхо), и из 10 секунд на ответ не должно уходить 3–4 секунды вопроса |
| Ответ кнопкой обрывает вопрос на полуслове | договаривать уже незачем |
| Уточнение «X или Y?» — только после «Джарвис» | в режиме FOLLOW_UP непонятная фраза — скорее разговор в комнате (как и раньше) |
| Голос выгружается после 30 с тишины и заранее загружается на «Джарвис» | с голосом в памяти процесс занимал 227 МБ при лимите ТЗ 150 МБ в простое; после выгрузки — 147 МБ; пока человек договаривает команду (1–2 с), голос успевает загрузиться (~0.5 с) |
| При старте голос загружается один раз для проверки | сломанный или неполный голос виден сразу в логе, а не на первом вопросе; без голоса Джарвис работает со звуковым пакетом |
| Кэш на 16 последних фраз | вопрос по одной и той же команде синтезируется один раз, повтор не требует загрузки голоса |
| В диалоге и в речи фраза команды — с подставленными слотами: «громкость на 40», а не «громкость на {level}» | человек видит и слышит то, что сказал |
| Из текста убираются управляющие символы | нулевой символ уронил бы библиотеку (`CString::new(...).unwrap()` внутри sherpa-onnx) |

### Замеры (release)

- Синтез: RTF 0.045, то есть секунда речи готова за 45 мс. Вопрос-разрешение (3.3 с речи)
  синтезируется за ~160 мс. Загрузка с прогревом — ~0.5 с.
- Память в простое (голос выгружен) — 147 МБ рабочего набора, 131 МБ частной памяти. С
  загруженным голосом — 227 МБ. После первой загрузки ~23 МБ остаются занятыми (данные espeak-ng и
  куча). Процессор в простое — ~2% одного ядра.
- Разборчивость (`default_voice_is_intelligible`): ключевые слова вопроса распознаются нашей
  моделью. Синтез VITS случаен, поэтому тест проверяет основы слов («откр»), а не точные слова:
  иногда слышится «открою». 8 прогонов подряд прошли без сбоев.

## Ждёт вас

Это касается вас лично, поэтому я этого не делал:

1. **Микрофон:** включить ME6S (кнопка на устройстве?) или подключить гарнитуру Fuxi-H3, затем
   `jarvis --check` должен показать «Сигнал: есть».
2. **Образец голоса:** `jarvis --enroll` — 5 раз «Джарвис» (1–2 минуты).
3. **Проверка на живом голосе:** запустить `jarvis`, сказать «Джарвис» с разных мест комнаты; в логе
   видны задержка (`reply_ms`) и сходство голоса (`voice`). Если не откликается —
   `jarvis --record test.wav` + `jarvis --bench test.wav` покажут, что слышит модель.
   Затем: «Джарвис, открой ютуб» → Джарвис спросит разрешение (голос + окно) → «всегда» →
   потом без «Джарвис» — «включи музыку», «громче». В логе — `since_heard_ms` (от фразы до
   действия), в `logs/actions.*.jsonl` — журнал. Проверьте Ctrl+Alt+F12 и «Джарвис, стоп».
4. **Голос синтеза:** громкость вывода сейчас 0% — сначала поднимите её. Затем послушайте
   голоса и выберите свой (`voice.tts` в `config/user.toml`):
   `jarvis --say "Сэр, команда открой ютуб откроет YouTube в браузере. Разрешить?" --voice dmitri`,
   затем то же самое с `--voice ruslan`, `--voice denis`, `--voice irina`.
5. **GitHub:** коммиты только локальные; `git push`, когда решите.
