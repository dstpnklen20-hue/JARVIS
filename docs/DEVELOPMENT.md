## Этап 0 — каркас

**Сделано:** Cargo workspace, конфиг (`default.toml` + `user.toml`) со строгой проверкой, логи с
ротацией, `jarvis --check`, скрипт скачивания моделей с проверкой SHA-256, `CLAUDE.md`, `README.md`.

**Окружение:** Windows 11 Pro 24H2, Core Ultra 9 275HX (24 потока), 32 ГБ, RTX 5070 Ti. Rust 1.99 и
VS 2022 Build Tools поставлены через winget.

| Решение | Почему |
|---|---|
| Workspace прямо в `F:\JARVIS`, а не в подпапке `jarvis/` | ваш выбор; ТЗ лежит рядом и попадает в git |
| Крейты создаются по мере надобности, а не все сразу | пустые заглушки только мешают; на этапе 0 — `core`, `platform`, `app` |
| `user.toml` накладывается поверх `default.toml`; ключ, которого нет в `default.toml`, — ошибка | опечатка в имени параметра ловится сразу, а не молча игнорируется |
| Все ошибки конфига выводятся сразу, с файлом, параметром и причиной | не нужно чинить по одной |
| Ошибки не повторяют причину в тексте, цепочку печатает `error_chain` | раньше сообщения дублировались |
| Описание ресурсов в одном файле `scripts/assets.json` | его читают и скрипт скачивания, и `--check` — нет расхождений |
| Метка `.jarvis-verified` с хешем архива в папке ресурса | `--check` за миллисекунды знает, что папка из проверенного архива нужной версии |
| `curl.exe` + `tar.exe` вместо `Invoke-WebRequest`/`Expand-Archive` | первый оборвал загрузку 1.9 ГБ без докачки, второй очень медленный |
| `.ps1` со строками на русском — в UTF-8 с BOM | Windows PowerShell 5.1 иначе читает их как ANSI |
| Время в логах местное | по UTC неудобно сверять события |

## Этап 1 — слух

### Главное решение: замена устаревших компонентов ТЗ

Перед этапом выяснилось, что часть предложенных в ТЗ компонентов давно не обновлялась. Вы
попросили взять лучшие актуальные альтернативы. Варианты проверены прототипом на тестовых фразах.

| В ТЗ | Проблема | Выбрано | Почему |
|---|---|---|---|
| `rustpotter` (wake word) | без обновлений с 2023 | потоковое распознавание русской речи + поиск слова «джарвис» + проверка голоса | английский keyword spotting (sherpa-onnx, gigaspeech) не услышал русское «Джарвис» даже при минимальном пороге; русская модель слышит его и стоит 1.7% одного ядра |
| `vosk` + libvosk 0.3.45 | крейт — 2024, сборка под Windows — 2022 | sherpa-onnx (k2-fsa, официальный Rust-крейт, 2026) + `zipformer-small-ru-vosk` (2025) | это новое поколение моделей той же команды Vosk: потоковая, частичные результаты, 23 МБ |
| полная модель Vosk 0.42 (1.9 ГБ) | — | GigaAM v3 (Сбер, 2025) на этапе 7 | точнее и в 10 раз меньше |
| `webrtc-vad` | без обновлений с 2019 | Silero VAD (TEN VAD — альтернатива в конфиге) | оба в sherpa-onnx, 0.2% CPU |
| обучение wake word на голосе (rustpotter) | — | `jarvis --enroll`: 5 записей → вектор голоса (CAM++) + как модель слышит ваше «Джарвис» | отсекает чужие голоса и ТВ; заодно подстраивает словарь под ваше произношение |

Отвергнуто: **T-one** (Т-Банк) — распознаёт точнее всех, но работает на 8 кГц кусками по 300 мс,
текст готов через 0.7–1 с; **Porcupine** — закрытый, нужен ключ; **openWakeWord** — для своего слова
нужно отдельное обучение на Python (можно добавить позже за тем же трейтом `WakeWordEngine`).

### Остальные решения этапа

| Решение | Почему |
|---|---|
| Архив нативной библиотеки sherpa-onnx качает наш скрипт с проверкой SHA-256 (хеш совпадает с опубликованным на GitHub), сборка берёт его через `SHERPA_ONNX_ARCHIVE_DIR` | сборочный скрипт крейта качает библиотеку без проверки |
| Статический рантайм C (`crt-static`) | библиотека собрана с `/MT`; два рантайма C в одном процессе — разные кучи (было предупреждение LNK4098). Плюс: `jarvis.exe` не требует `vcruntime*.dll` |
| Звук ответа через `cpal` напрямую, без `rodio` | `rodio` 0.22 тянул вторую копию `cpal`, 0.23 вышел в день разработки; свой проигрыватель на 150 строк держит поток вывода открытым — ответ без задержки на открытие устройства |
| Ресемплинг 48 → 16 кГц — FFT-ресемплер `rubato` | качественный антиалиасинг (проверено тестом: 12 кГц подавляется, а не заворачивается) |
| Callback микрофона и вывода: только копирование через lock-free `ringbuf`, без блокировок и аллокаций | требование ТЗ к потоку реального времени |
| Срабатывание по **частичному** результату распознавания | «Джарвис» ловится, пока слово ещё дописывается («джарви»): в среднем на 100–200 мс раньше |
| Сопоставление слова: расстояние Левенштейна ≤ 1, но не больше трети длины; слова короче 4 букв не сравниваются | ловит «жарвис», «джарвиз», «джавис»; не ловит «дарвин», «сервис», «джаз» |
| Поток распознавателя **пересоздаётся**, а не `reset()` | `reset()` в sherpa-onnx не сбрасывает энкодер: хвост прошлой фразы превращал «джарвис» в «орвис» (поймано тестом) |
| Встроенное правило «2 с тишины → сброс» не исполняется вслепую | модель видит речь с задержкой, сброс мог прийтись на начало слова; теперь на пустой тишине сброс только когда звук действительно тихий, после законченной фразы — сразу; поток не длиннее 60 с |
| Порог сходства голоса — между 0.30 и 0.55, запас 0.20 от худшего образца | синтетика даёт 0.96–0.98, и порог упирался в 0.70; живой голос меняется сильнее (0.5–0.8) — при 0.70 были бы частые отказы. Чужие голоса — меньше 0.3 |
| Пока Джарвис говорит, на вход подаётся тишина (`MuteGate`) | он не слышит сам себя (раздел 4.1 ТЗ); время потока при этом идёт |
| На паузе микрофон закрывается полностью | гаснет индикатор микрофона Windows |
| Сбой буфера микрофона (xrun) не считается потерей устройства | в первом живом тесте микрофон переоткрывался каждые 2 с — само переоткрытие вызывало новые сбои |
| Конвейер слуха в отдельном потоке под присмотром: паника → перезапуск (до 5 раз) | падение не роняет приложение (раздел 10 ТЗ) |
| Пробуждение главного потока — `PostThreadMessageW` + таймер 250 мс | сообщения потоку теряются, пока открыто меню трея; таймер подхватывает накопленное |
| `jarvis --stop` через именованное событие Windows | у фонового процесса нет окна — без этого его не остановить мягко; пригодится установщику |
| `--check` замеряет уровень сигнала микрофона | в живом тесте ME6S отдавал цифровую тишину — теперь это видно сразу |
| Логика ядра на потоках и каналах `std`, без `tokio` | на этапе 1 нечего делать асинхронно; `tokio` появится вместе с сетью (LLM, этап 7) |
| Стандартный звуковой пакет — голос Windows «Pavel» через WinRT, тишина по краям обрезается | мужской голос, без внешних сервисов; обрезка убирает ~100 мс задержки перед «Да, сэр» |
| Тестовые записи синтезируются скриптом и лежат в git (2.6 МБ) | тесты конвейера без живого микрофона (раздел 10 ТЗ) |
| Тесты на моделях помечены `#[ignore]` | моделей нет в git; запуск: `cargo test --release -- --include-ignored` |

## Этап 2 — команды

**Сделано:** манифесты команд (`commands/*/command.toml`), пакеты `browser` и `media`;
нормализация (регистр, ё, паразиты, числа словами) и нечёткое сопоставление (`jarvis-nlu`);
исполнители `open_url`, `media`, `say` (`jarvis-actions`); распознавание команды после «Джарвис»;
автомат `LISTENING → EXECUTING → FOLLOW_UP`; раннее решение по частичному тексту; `--bench` для
команд; пункт «Команды» в `--check`.

| Решение | Почему |
|---|---|
| Вместо ограниченной грамматики Vosk — подсказки (hotwords) из фраз команд + нечёткое сопоставление | новая модель не поддерживает грамматику; подсказки при силе 1.5 не искажают речь (при 2.5 «громкость» → «громчесть»), а сопоставление прощает ослышки |
| Словарь `bpe.vocab` для подсказок выгружается из `bpe.model` своим разборщиком protobuf | без Python; формат простой |
| Подсказки только из кириллических фраз | латиницы нет в словаре русской модели — sherpa-onnx не закодировал бы подсказку |
| Один распознаватель на слово активации и команды (два потока) | с двумя копиями модели память была 186 МБ, с одной — 124 МБ (цель ≤ 150) |
| Распознавание команд включается только после «Джарвис» и получает звук **с начала слова активации** из буфера | в простое процессор не тратится; «Джарвис, открой ютуб» на одном дыхании тоже работает |
| Сходство фраз — нормированный Левенштейн по исходному и по отсортированному порядку слов | «ютуб открой» = «открой ютуб»; «выключи звук» и «включи музыку» различаются надёжно |
| Почти равные кандидаты разных команд — «переспросить» (пока звучит «Не понял, сэр») | вопрос «X или Y?» голосом — с синтезом речи на этапе 5 |
| Непонятная фраза в FOLLOW_UP игнорируется молча | скорее всего это разговор в комнате, а не команда |
| Мгновенное решение по частичному тексту: точная фраза или однозначное начало («открой ю…» → «открой ютуб», покрыто ≥ 60 % фразы); иначе — после 300 мс стабильного текста; иначе — по концу фразы | модель выдаёт текст блоками по 0.64 с (её экспорт: `decode_chunk_len = 64`), последнее слово запаздывает на 0.3–0.6 с; без этого среднее было ~800 мс |
| Конец фразы — 800 мс тишины, а не 500 | при 500 фраза рвалась на части («поставь» \| «паузу»): 9–10 из 13 верно против 13 из 13 |
| «но» — слово-паразит | модель часто пишет так «ну» |
| `open_url` — только `http(s)://`, проверка и при загрузке, и перед запуском; запуск через `ShellExecuteW` одним параметром, без оболочки | `file:`, `javascript:` и т. п. из манифеста не должны запускаться |
| Мультимедиа — виртуальные клавиши через один `SendInput` (нажатие и отпускание в одном пакете) | клавиша не может «залипнуть»; скан-коды для игр — этап 4 |
| Действие — в отдельном потоке с перехватом паники и тайм-аутом 10 с; поздний результат игнорируется по номеру | сбой или зависание действия не роняет и не вешает ядро (раздел 2.5) |
| Пути в `say` — строго внутри папки пакета (без `..` и абсолютных) | чужой пакет не может читать файлы вне своей папки |
| Ответ после команды по умолчанию `ok`; мультимедиа — `none` | «Готово, сэр» после каждого «громче» раздражает |
| Ключ ответа «Запрос выполнен» — `ok` (был `done`) | так в примере манифеста из ТЗ |
| В проигрывателе держатся последние 4 произвольных клипа | чтобы память клипа не освобождалась в потоке реального времени |
| `jarvis-app` — библиотека + бинарник | разбор команд и симуляция проверяются тестами на настоящих записях |

**Важно:** до этапа 3 команды выполняются **без вопроса-разрешения** (так устроен порядок этапов
в ТЗ). Безопасно потренироваться можно с `general.dry_run = true`. Этап 3 идёт сразу следом.

## Ждёт вас

Это касается вас лично, поэтому я этого не делал:

1. **Микрофон:** включить ME6S (кнопка на устройстве?) или подключить гарнитуру Fuxi-H3, затем
   `jarvis --check` должен показать «Сигнал: есть».
2. **Образец голоса:** `jarvis --enroll` — 5 раз «Джарвис» (1–2 минуты).
3. **Проверка на живом голосе:** запустить `jarvis`, сказать «Джарвис» с разных мест комнаты; в логе
   видны задержка (`reply_ms`) и сходство голоса (`voice`). Если не откликается —
   `jarvis --record test.wav` + `jarvis --bench test.wav` покажут, что слышит модель.
   Затем: «Джарвис, открой ютуб», потом без «Джарвис» — «включи музыку», «громче». В логе —
   `since_heard_ms` (от фразы до действия).
4. **GitHub:** коммиты только локальные; `git push`, когда решите.
